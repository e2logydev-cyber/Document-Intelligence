🎯 System Overview

Overview

What it does in one sentence: — when an email with attachments arrives, Flow 1 saves the file, extracts its data using AI Builder or expressions, and stores the structured results in a SharePoint list. - When a file is uploaded to SharePoint, Flow 2 matches it against a mapping table and automatically routes it to the correct folder while emailing the owner

SharePoint

SourceFiles Library

Document library where files are uploaded. Tracks processing status, matched pattern, and routing destination per file.

SharePoint

FileMappingTable List

Rule engine — maps file name patterns (e.g. INV_*) to target folders, email templates, owners, and processing types.

SharePoint

ProcessedData List

Audit and results log — stores extracted data, source file links, processing status, timestamps, and originating flow name.

Power Automate

Flow 1 — Email Extraction

Triggers on inbound email with attachments. Saves files to SharePoint, extracts structured data using AI Builder, and logs results to ProcessedData.

Power Automate

Flow 2 — File Routing

Triggers on file upload. Matches filename against mapping rules, moves the file to the correct folder, and sends an owner notification email.

Design Principle

SharePoint as the single source of truth. Both flows read routing rules from FileMappingTable and write all results to ProcessedData. Updating a rule in the mapping table immediately changes how both flows behave — no flow editing required.

Flexibility

Add or change routing rules by editing the FileMappingTable list — no code or flow changes needed. IsActive flag enables/disables rules instantly.

Priority Control

The Priority number column in FileMappingTable controls which rule wins when multiple patterns match the same filename.

Full Audit Trail

Every processed file — routed or extracted — is logged to ProcessedData with status, timestamp, and the flow that handled it.

AI-Powered Extraction

AI Builder models can extract structured fields from PDFs and invoices without manual parsing logic or regular expressions.

🗂️ Phase 1 — SharePoint Setup

SharePoint Setup

Three SharePoint structures must be created before building either flow. These act as the data backbone for the entire system.

Step 1 — Create the Document Library: SourceFiles

📁 SourceFiles — Document Library

Go to your SharePoint site → click New → Document Library → name it SourceFiles. This is where files are uploaded and where Flow 1 is triggered. Add the following custom columns:

Column NameTypeOptions / Notes
StatusChoiceOptions: Unprocessed Processed — default: Unprocessed
MatchedPatternSingle line of textFilled by the flow — stores the FilePattern that matched this file
RoutedToSingle line of textFilled by the flow — stores the TargetFolder the file was moved to
Document Library Flow 1 Trigger Source Status Tracking

Step 2 — Create the Mapping Table: FileMappingTable

📋 FileMappingTable — SharePoint List

Click New → List → name it FileMappingTable. Rename the default Title column to FilePattern — this holds glob-style patterns like INV_* or HR_*. Add the following columns:

Column NameTypeNotes
FilePattern (Title)Single line of texte.g. INV_*, HR_* — pattern to match against uploaded filenames
TargetFolderSingle line of textDestination path, e.g. /Invoices or /HR/Documents
EmailTemplateMulti-line textEmail body template — use dynamic tokens for file name, date, etc.
OwnerPerson or GroupReceives the notification email when a file matches this rule
EmailSubjectSingle line of textSubject line for the notification email
PriorityNumberLower number = higher priority. Used for conflict resolution when multiple patterns match
ProcessingTypeChoiceOptions: Route Extract Notify
IsActiveYes/NoDefault: Yes. Set to No to disable a rule without deleting it
Rule Engine No-Code Rule Updates Flow 1 Data Source

Step 3 — Create the Results List: ProcessedData

📊 ProcessedData — SharePoint List

Click New → List → name it ProcessedData. Both flows write to this list after processing a file. Add the following columns:

Column NameTypeNotes
TitleSingle line of textUse the file name or email subject as the title
ExtractedDataMulti-line textJSON string of all extracted fields from the document
SourceFileHyperlinkLink to the original file in SharePoint
StatusChoiceOptions: Pending Processed Failed
TimestampDate and TimeSet by the flow using utcNow() at time of processing
FlowNameSingle line of texte.g. Flow1 or Flow2 — identifies which flow created the record
Audit Log Extraction Results Written by Both Flows
📧 Phase 3 — Flow 1

Flow 1 — Email Inbound Data Extraction

Triggered when an email with attachments arrives. Saves the attachment to SharePoint, extracts structured data using AI Builder or expressions, then stores results in ProcessedData.

Create flow: Power Automate → Create → Automated cloud flow → Name it Flow1_EmailExtraction → Trigger: "When a new email arrives (V3)" (Outlook) → set Has Attachment = Yes. Optional: set Subject Filter to a keyword like [DATA] to avoid processing all emails.

1
Trigger — New email with attachment

The flow fires when a new email arrives in the configured Outlook mailbox with Has Attachment = Yes. Trigger outputs include subject, sender, body, and the Attachments array. Add a Subject Filter (e.g. [DATA]) to target only relevant emails.

2
Check and Loop Attachments

Add Condition: Attachments is not empty → in Yes branch, add "Apply to each" → value = Attachments from trigger.

  • Inside the loop, add another Condition to filter file types:
  • items('Apply_to_each')?['Name'] contains .pdf or .xlsx
  • This avoids processing image attachments or unrelated files
3
Save Attachment to SharePoint

Add action: "Create file" (SharePoint):

  • Site Address = your SharePoint site
  • Folder Path = /Inbox/Attachments (a staging folder)
  • File Name = Name from attachment
  • File Content = ContentBytes from attachment
4
Extract Data from File

Choose the appropriate extraction method:

  • Option A — Expressions: Use decodeBase64() on file content; use "Parse JSON" action for JSON files; use string split/trim expressions for CSV/text files
  • Option B — AI Builder (recommended for PDFs/invoices): Add action "Extract information from documents" → select your pre-trained model (invoice, receipt, or custom) → Document = file content from SharePoint. Returns structured fields: invoice number, date, amount, vendor, etc.
5
Write Extracted Data to ProcessedData

Add action: "Create item" (SharePoint) → List = ProcessedData. Map fields:

  • Title: email subject or file name
  • ExtractedData: string() expression wrapping the extracted JSON fields
  • SourceFile: SharePoint file URL from Step 3 output
  • Status: Processed
  • Timestamp: utcNow()
  • FlowName: Flow1
6
Update Status & Notify Sender
  • Update file properties: Set Status = Processed on the saved SharePoint file
  • Send reply email: "Send an email (V2)" → To = sender address from trigger, Subject = Re: [subject], Body = confirmation message with file name and extraction summary

Extraction Flow Summary

Email Arrives → Filter Attachments → Save to SharePoint → Extract (AI Builder) → Write ProcessedData → Reply to Sender

Extraction Options Compared

Option A — Expressions

Simple / Text-Based Files

Best for CSV, JSON, or plain text attachments. Use decodeBase64(), Parse JSON, and string split expressions. No additional licences required.

Option B — AI Builder

PDFs, Invoices, Receipts

Use "Extract information from documents" with a pre-trained or custom model. Returns structured named fields — invoice number, total, vendor, date — without any parsing logic.

🔁 Phase 2 — Flow 2

Flow 2 — File Upload Routing & Email

Triggered when a file lands in SourceFiles. Matches the filename against FileMappingTable rules, routes the file to the correct folder, emails the owner, and logs the result.

Create flow: Power Automate → Create → Automated cloud flow → Name it Flow2_FileUploadRouting → Trigger: "When a file is created (properties only)" (SharePoint) → set Site Address and Library Name = SourceFiles.

1
Trigger — File created in SourceFiles

The flow fires automatically when any new file is created (uploaded) in the SourceFiles document library. The trigger outputs include the file ID, name with extension, and metadata.

2
Get File Properties

Add action: "Get file properties" (SharePoint) → Site Address = your site, Library = SourceFiles, ID = ID from trigger outputs. This retrieves the full filename with extension needed for pattern matching.

3
Query FileMappingTable

Add action: "Get items" (SharePoint) → List = FileMappingTable.

  • Filter Query: IsActive eq 1
  • Order By: Priority asc — ensures highest priority rule wins
4
Match File Pattern — Apply to Each

Add action: "Apply to each" → loop through the Get items results. Inside the loop, add a Condition:

  • Expression (left): startsWith(triggerOutputs()?['body/{FilenameWithExtension}'], items('Apply_to_each')?['FilePattern'])
  • For wildcard matching: contains(filename, replace(FilePattern, '*', ''))
  • Condition operator: is equal to true
5
YES Branch — Route, Notify & Log

When a pattern matches, execute all four actions:

  • Move file: "Move file" (SharePoint) → Current Site = source, File to Move = file identifier, Destination = TargetFolder from matching mapping row
  • Send email: "Send an email (V2)" (Outlook) → To = Owner email, Subject = EmailSubject, Body = EmailTemplate with dynamic file name and date inserted
  • Update file properties: Set Status = Processed, MatchedPattern = FilePattern from matched row, RoutedTo = TargetFolder
  • Log to ProcessedData: "Create item" → Title = file name, Status = Processed, Timestamp = utcNow(), FlowName = Flow1
6
NO Branch — Mark Unprocessed

If no pattern matches the filename:

  • "Update file properties" → set Status = Unprocessed
  • Optional: "Send an email" alert to an admin notifying them of an unmatched file

Routing Flow Summary

File Uploaded → Get Properties → Query Rules → Pattern Match → Move + Email → Log Result
🛠️ Technology Stack

Technology Stack

ComponentTechnologyPurpose
File Storage SharePoint Document Library SourceFiles library stores uploaded files and tracks routing status per file.
Rule Engine SharePoint List (FileMappingTable) Configurable pattern-matching rules. Update rules without touching any flow logic.
Audit & Results SharePoint List (ProcessedData) Central log of all processed files — extracted data, source links, status, timestamps.
Email Extraction Flow Power Automate — Automated Cloud Flow Flow 1: triggers on email, saves attachments, extracts structured data, stores in list.
File Routing Flow Power Automate — Automated Cloud Flow Flow 2: triggers on file upload, matches patterns, moves files, sends emails, logs results.
Data Extraction AI Builder (Power Platform) Pre-trained document models extract named fields from PDFs, invoices, and receipts without manual parsing.
Email Connector Outlook (Office 365) Used in both flows — trigger for incoming email and action for outbound owner notifications.

Platform Advantages

No-Code Rules

Routing rules live in a SharePoint list. Any authorized user can add, edit, or deactivate rules without opening Power Automate.

Scalable

Add more patterns to FileMappingTable to handle new file types or departments without changing any flow logic.

Priority-Driven

Conflict resolution is built in — when multiple patterns match, the lowest Priority number wins. No ambiguous behavior.

AI-Ready

AI Builder slots directly into Flow 1 — upgrade from expression-based extraction to model-based extraction by swapping one action.
